# 一人でnoteを続けるのが辛かったので、AIに運営チームを作らせました

「今日は何を書こう」「そもそも誰に向けて書くんだっけ」「公開したけど、これって伸ばすためにどう動けばいいんだろう」——note を一人で回していると、この3つの問いが毎回頭の中をぐるぐるします。企画も執筆も編集も拡散も、全部自分でやらないといけない。会社なら分業する仕事を、個人発信では一人で背負うのが当たり前になっています。

私はこのしんどさを解消するために、Claude Code（Anthropic製のAIコーディングツール）を使って「運営チーム」を作りました。コードを書くためのツールを、コードを書かない業務に使った話です。

## 一人でnoteを続けることの限界を感じていた

私がぶつかっていたのは、いわゆる「ネタ切れ」ではありませんでした。むしろ逆で、書きたいことは頭の中にたくさんある。でも、それを

- 誰に向けた、どんな企画にするか整理する
- 実際に読みやすい文章に落とし込む
- 誤字脱字や構成の甘さをチェックする
- 有料記事にするなら価格やマガジン設計を考える
- 投稿後にSNSでどう告知するか考える

という工程に分解して、毎回全部一人でこなすのが単純に体力的にきつかったんです。本業もある中で、note のためだけに毎日この5役をこなすのは、続けようとすればするほど息切れする構造でした。

「ネタがない」のではなく「役割が多すぎる」ことが、更新が止まる本当の原因だったと気づいたのがきっかけです。

## Claude Codeに「運営チーム」を作らせるという発想

Claude Code は普段、プログラムのコードを書いたりバグを直したりするために使うツールです。ただ、実際に触ってみると分かるのですが、Claude Code の本質は「指示書（Markdown）を読み込んで、それに沿って作業してくれるエージェント」を作れることにあります。コードである必要はなく、指示書が「企画のやり方」や「文章のトンマナ」でも成立するわけです。

そこで私は、人を新しく雇う代わりに、役割ごとに専門特化した「サブエージェント」（特定の役割・指示だけを与えられたAIの担当者、というイメージです）を4人分定義することにしました。1つのAIに全部任せると、企画の視点と編集の視点が混ざってしまい、どっちつかずの記事になりがちだったからです。人間のチームで分業する理由と同じで、「役割ごとに視点を分ける」こと自体に価値があると考えました。

## 4人のサブエージェントを紹介します

実際に作ったのは、次の4つの役割です。

**企画（プランナー）**
ネタ出しと、無料パート・有料パートの切り分け、記事カレンダーの作成を担当します。「このテーマは誰の悩みに刺さるか」「どこまで無料で見せて、どこから有料にするか」を最初に決める係です。

**執筆（ライター）**
プランナーが作った構成骨子を受け取り、実際にnoteに貼り付けられる完成度の本文を書きます。冒頭200〜300字のフック文（読者が「読む価値がある」と判断する導入部分）を必ず入れる、というルールを持たせています。

**編集（エディター）**
校正と構成チェックに加えて、有料記事の場合は「ここから先は有料」という壁をどこに置くか、そこまでで無料パートとしての価値が成立しているかを見ます。書いた本人だと見落としがちな、読者目線でのチェック役です。

**グロース戦略**
価格設定、マガジン設計、SNSで告知するときの訴求ポイント整理、CTA（読者に取ってほしい行動の呼びかけ）の最適化を担当します。書くこと自体ではなく、書いた記事をどう届けるかに専念する役割です。

この4人に共通の「ブランド定義書」（トンマナ、一人称、ターゲット読者などをまとめたマスタードキュメント）を読ませることで、担当が変わっても文章の一貫性が保たれるようにしています。さらに「企画→執筆→編集を一気通貫で行う」ワークフローを1つのコマンドとして用意し、新しい記事を書くときは毎回このワークフローを起点にする、というルールにしました。

## 実際に動かしてみて分かったこと

運用してみて一番驚いたのは、**企画とフック文づくりの負担がほぼなくなったこと**です。今まで1本の記事を書く前に、「これ誰に向けた話だっけ」と迷う時間が地味に長かったのですが、プランナー役が先に想定読者と骨子を言語化してくれるので、執筆に集中できるようになりました。

編集役に「ここから先の有料パートで何が得られるか、一文で分かるようにして」とチェックさせることで、有料記事の壁の作り方にも一定の型ができました。

一方で、限界もはっきり感じています。AIが出してくる企画やコピーは「それっぽく整っている」けれど、実際に読者の反応を見て「これは刺さった」「これは滑った」を判断するのは、結局私自身の役目です。数値目標や価格改定、公開するかどうかの最終判断もすべて人間側に残しています。

AIチームは「叩き台を高速に、かつ役割ごとの視点で作ってくれる」存在であって、「代わりに責任を持って発信してくれる」存在ではない、というのが正直な実感です。ここは思っていた以上にはっきり線が引かれました。

## この仕組みは他の発信活動にも応用できる

この考え方は note に限らず、ブログ、メルマガ、社内報、さらには個人の営業資料づくりなど、「企画→制作→チェック→拡散」という流れを一人で回している作業全般に応用できると感じています。ポイントは、AIに全部を丸投げするのではなく、**自分がボトルネックになっている工程を洗い出し、そこだけ役割を切り出して専門のエージェントを作る**ことです。全部を一気に自動化しようとせず、一番しんどい工程から一つずつ任せていくくらいがちょうどいい距離感だと思います。

## まとめ

一人でnoteを続けるしんどさの正体は、ネタ切れではなく「企画・執筆・編集・拡散という複数の役割を一人で兼任していること」でした。Claude Code に役割ごとの指示書を与えて4人分のサブエージェントを作ったことで、企画とフック文づくりの負担は大きく減った一方、最終判断や読者の反応を見る目は結局自分に残る、というのが今のところの結論です。

次回は、実際にプランナー役・ライター役に渡している指示書の中身や、フック文を作るときに使っているプロンプトの具体例を、有料記事で詳しく紹介する予定です。「自分の発信にも応用してみたい」と思った方は、ぜひコメントで感想を聞かせてください。
